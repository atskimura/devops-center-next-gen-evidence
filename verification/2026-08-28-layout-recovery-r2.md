# 2026-08-28 落ちたレイアウト配置を戻す（R-2）

- 目的: **項目定義だけでなく、利用者が再び画面から使える状態まで安全に戻せるか**を確かめる。
- 使った org: `dcng-prod`（Hub）/ `dcng-dev1` / `dcng-stg`
- **予測を先に書いてから実行した。**
- R-1 では項目定義を3つの org に揃えたが、レイアウトの配置は戻らず
  項目レベルセキュリティも0件だった（→ [R-1 のログ](2026-08-27-recovery-r1.md)）

## 2. 「本番で後から加えた配置」を先に作る

判定条件に「別の配置を失わないか」があるので、材料を作った。
prod のレイアウトに `FullDeployVehicle__c` を直接配置した。

**実務では画面で操作するが、ドラッグの自動化が難しいので CLI で同じ状態を作った。**

```
sf project deploy start -o dcng-prod -d "force-app/main/default/layouts/Account-取引先 レイアウト.layout-meta.xml"
→ Changed / Succeeded（23:46:37 開始 / 23:46:43 完了）
```

この時点の prod のレイアウト: `DevSideNote__c` / `VerificationNote__c` / **`FullDeployVehicle__c`**

## 3. dev1 で配置を戻し、権限セットと一緒に運ぶ

**項目定義・レイアウト・権限セットを1つの作業項目にまとめた**（実務に近い形）。

| 何 | やったこと |
|---|---|
| レイアウト | `ProdOnlyNote__c` の `layoutItems` を追加 |
| 権限セット | `HybridTestAccess` に `Account.ProdOnlyNote__c` の項目権限を追加 |
| 項目定義 | 既に git にあるので触らない |

### `Conflict` で1回止まった

```
sf project deploy start -o dcng-dev1 -d <レイアウト> -d <権限セット>
→ Error (1): There are changes in the org that conflict with the local changes you're trying to deploy.
```

`sf project deploy preview` で見ると `Layout` と `PermissionSet` の2件だった。
**中身を確認すると org と git は一致していた**（配置されている項目が同じ）。
`sf` のソース追跡が持っている状態のずれで、`--ignore-conflicts` で通した。

**無条件に上書きすると R-2 の材料（prod の配置）が壊れる可能性があったので、
先に diff を取って確認した。** この切り分けに約50秒使った。

### deploy の直後に retrieve した

08-28 に決めた手順（→ セットアップに関する検証）に従った。
**レイアウトと権限セットでは形が変わらなかった**（差分は追加分だけ）。

## 4. 判定: 配置は戻るが、本番で後から加えた配置は失われた

**予測が両方当たった。**

| | 予測 | 結果 |
|---|---|---|
| `ProdOnlyNote__c` の配置 | 戻る | **戻った** |
| **`FullDeployVehicle__c` の配置** | 失われる | **失われた** |
| 昇格画面の警告 | 出ない | **出なかった** |
| 権限セットの項目権限 | 届く | **届いた**（`read` / `edit` ともに `true`） |

昇格後の prod のレイアウト。

```
DevSideNote__c
ProdOnlyNote__c      ← 戻った
VerificationNote__c
（FullDeployVehicle__c が消えた）
```

**レイアウトは差分マージされない。リポジトリの内容で丸ごと置き換わる。**

これは B-2b で「本番の配置が落ちる」と分かった現象と同じ機構である。
**復旧の昇格そのものが、本番で後から加えられた配置を消した。**

## 6. 分かったこと

- **配置は戻せる。** 項目定義・レイアウト・権限セットを1つの作業項目で運べる
- **ただし復旧の昇格が、本番で後から加えられた配置を消す。**
  レイアウトは差分マージされず、リポジトリの内容で置き換わる
- **警告は出ない。** 昇格の画面にも `DevopsRequestInfo` にも、
  配置が失われることを示すものは無かった
- 権限セットを同じ作業項目で運べば、**配置と項目権限の両方が揃う**
- API と CLI を使えば **8分39秒 / 画面操作1回**で通る

### 実務への意味（**未検証の提案**）

レイアウトは1ファイルなので、**昇格するファイルに本番の配置も入っていれば失われないはずである。**

```
git のレイアウト（今回の昇格前）    prod のレイアウト（今回の昇格前）
  DevSideNote__c                    DevSideNote__c
  VerificationNote__c               VerificationNote__c
                                    FullDeployVehicle__c  ← git に無い
```

**今回はこれをやらずに `ProdOnlyNote__c` だけを追加して昇格した。**
提案は次の形になる。

1. 本番のレイアウトを retrieve する
2. リポジトリのレイアウトと diff を取る
3. 本番にしかない配置（`FullDeployVehicle__c`）を**同じファイルに書き足す**
4. 戻したい配置（`ProdOnlyNote__c`）も**同じファイルに書き足す**
5. 両方入った1ファイルを昇格する

**⚠ この手順は確かめていない。** 1ファイルの置き換えなので両方残ると考えられるが、
実機で通していない。R-6 の乖離検知（`manifest` で retrieve して `git status` を見る）が
2の材料になる。

## 7. 未確認として残したもの

  何がずれを作ったかは追えていない
